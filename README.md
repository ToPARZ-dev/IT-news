# ToPARZ IT News

Xで複数の人が話題にしたIT・AIの動きを、読み物の記事にまとめる日刊ニュース。原稿はMarkdownで書き、スクリプトでHTML記事を生成してGitHub Pagesで公開する。

公開URL: https://toparz-dev.github.io/IT-news/

## 構成

| パス | 内容 |
| ---- | ---- |
| `content/YYYY-MM-DD.md` | 原稿（1日1ファイル）。ここだけ人が書く |
| `templates/article.html` | 記事ページのテンプレート |
| `templates/index.html` | トップページのテンプレート |
| `assets/style.css` | 共通スタイル（ライト・ダーク対応） |
| `scripts/build.py` | 原稿からHTMLを生成する（Python 3.9以上、依存なし） |
| `scripts/publish.sh` | 生成 → コミット → push → 公開URLの応答確認 |
| `articles/YYYY-MM-DD.html` | 生成された記事ページ |
| `index.html` / `latest.html` / `feed.xml` | 生成されたトップ・最新号へのリダイレクト・RSS |
| `site.json` | サイト名・タグライン・公開URL・編集方針 |

生成物（`articles/`・`index.html`・`latest.html`・`feed.xml`）もコミットする。GitHub Pagesがそのまま配信するため、ビルド用のワークフローは不要。

このリポジトリは公開されている。社内の非公開情報、X投稿のURL、Webhook等の秘密情報を入れない。

## 毎日の手順

1. `content/YYYY-MM-DD.md` を書く（書き方は次節）
2. 生成して確認する

   ```bash
   python3 scripts/build.py --check   # 原稿の構造を確認。[注意] が出たら原稿を直す
   python3 scripts/build.py           # articles/・index.html・latest.html・feed.xml を生成
   ```

   ブラウザで `articles/YYYY-MM-DD.html` を開いて確認する
3. 公開する

   ```bash
   bash scripts/publish.sh YYYY-MM-DD --wait
   ```

   コミット・push・公開ページが今回の内容になるまでの待機（最大5分）を行い、URLを表示する。記事には生成時に `build-id`（原稿・テンプレート・CSS・設定から決まる識別子）を埋め込んであり、公開ページの `build-id` が一致したら成功、時間切れは終了コード2。`--wait` を付けなければpushまで
4. 表示されたURLをDiscord等に通知する（通知の手順は経営管理リポジトリの `$ai-news-discord` スキル）

## 原稿の書き方

箇条書きで並べず、読み物として書く。1本の記事は「見出し → リード → 何が起きたか → 分析 → ただし → 締めの一文 → 出典」の順。

```markdown
---
date: 2026-09-30
scope: Xホームと関連投稿。直近24時間を中心に確認
---

## 何が変わるかが伝わる見出し
リード段落。具体的な報告や意外な事実で、読者を引き込む1〜3文。

何が起きたかを説明する段落。前提を1文で置き、発表内容や数値を出典を明らかにして書く。
段落は空行で区切る。

### どこで効きそうか（分析）
この変化が仕事や制作にどうつながるか、理由とともに書く段落。

### ただし
成立条件、まだ分からない点、誇張を避けるための補足。

> 読者が持ち帰る締めの一文。

出典：[公式発表](https://example.com/announcement)
```

- ファイル名は `YYYY-MM-DD.md`（1日1ファイル）。先頭の `---` で囲んだ部分は号の情報で、`date`（必須、ファイル名と同じ日付）と `scope`（確認範囲）を書く。`title` を書くとページタイトルを差し替えられる。日付がファイル名と違うと生成を中止する
- `## ` で始まる行が1本の記事の見出し。1号に通常2〜4本
- 見出し直後の段落はリードとして少し大きく表示される
- `### ` は小見出し。語で縦線の色が決まる
  - 「分析」「示唆」「なぜ」「どう」「どこで」「見方」「考察」「影響」「意味」「注目」「ポイント」を含む → 青（分析）
  - 「ただし」「注意」「制約」「留意」「未確認」「リスク」「課題」「限界」「懸念」「落とし穴」「分からない」を含む → 黄（注意）
  - それ以外 → 灰
- `> ` で始まる行は「ひとこと」として強調表示される。記事の締めに1つ
- `出典：[名前](URL)` の行（「出典」「参考」「参照」「一次資料」＋「：」で始まる行）は本文から外れ、記事末尾の出典欄にドメイン付きで表示される。リンク以外の文もそのまま残る
- 箇条書き（`- `、入れ子は2スペース下げ）も使えるが、列挙が必要なときだけにする
- 本文中で使えるMarkdownは、リンク `[名前](URL)`・太字 `**語**`・コード `` `語` `` のみ
- 段落の途中で改行しても1つの段落になる。日本語どうしは詰めて結合し、英数字や記号どうしの間には空白を入れる
- 最初の `## ` より前に段落を書くと、号全体の前書きとして表示される
- `--check` は、リード・本文・出典・注意の小見出し・締めの一文がない記事に `[注意]` を出す。本人の報告だけで公式資料がない記事の「出典がありません」は、本文に「本人の報告」と明示してあれば受容してよい。それ以外は原稿を直す

## 公開設定（初回のみ）

GitHubリポジトリの Settings → Pages で次のとおり設定する。

- Source: Deploy from a branch
- Branch: `main` / `/ (root)`

`.nojekyll` を置いているので、Jekyllの処理は行われずファイルがそのまま配信される。

## デザインを変えるとき

- 見た目は `assets/style.css`、ページ構造は `templates/*.html`、記事内の部品（見出し・節・ひとこと・出典欄）は `scripts/build.py` の `render_*` 関数で決まる
- 変更後は `python3 scripts/build.py` を再実行すると、過去の記事もすべて新しいデザインで生成し直される
