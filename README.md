# ToPARZ IT News

AIを仕事で使う人のための日刊ニュース。Xで話題になった動きを、発表元の資料と報道で確かめて記事にする。原稿はMarkdownで書き、スクリプトでHTML記事を生成してGitHub Pagesで公開する。

公開URL: https://toparz-dev.github.io/IT-news/

## 構成

| パス | 内容 |
| ---- | ---- |
| `content/YYYY-MM-DD.md` | 原稿（1日1ファイル）。ここだけ人が書く |
| `templates/article.html` | 記事ページのテンプレート |
| `templates/index.html` | トップページのテンプレート |
| `assets/style.css` | 共通スタイル（ライト・ダーク対応） |
| `scripts/build.py` | 原稿からHTMLを生成する（Python 3.9以上、依存なし） |
| `scripts/publish.sh` | 生成 → コミット → push → 公開URLの応答確認 |
| `articles/YYYY-MM-DD.html` | 生成された記事ページ |
| `index.html` / `latest.html` / `feed.xml` | 生成されたトップ・最新号へのリダイレクト・RSS |
| `site.json` | サイト名・タグライン・公開URL・編集方針 |

生成物（`articles/`・`index.html`・`latest.html`・`feed.xml`）もコミットする。GitHub Pagesがそのまま配信するため、ビルド用のワークフローは不要。

このリポジトリは公開されている。社内の非公開情報、X投稿のURL、Webhook等の秘密情報を入れない。原稿にXへのリンクがあると、生成は止まる。

## 毎日の手順

1. `content/YYYY-MM-DD.md` を書く（書き方は次節）
2. 検査して生成する

   ```bash
   python3 scripts/build.py --check YYYY-MM-DD   # その号の構造と [注意] を表示する。[注意] が出たら原稿を直す
   python3 scripts/build.py                      # articles/・index.html・latest.html・feed.xml を生成
   ```

   ブラウザで `articles/YYYY-MM-DD.html` を開いて確認する
3. 公開する

   ```bash
   bash scripts/publish.sh YYYY-MM-DD --wait
   ```

   コミット・push・公開ページが今回の内容になるまでの待機（最大5分）を行い、URLを表示する。記事には生成時に `build-id`（原稿・テンプレート・CSS・設定から決まる識別子）を埋め込んであり、公開ページの `build-id` が一致したら成功、時間切れは終了コード2。`--wait` を付けなければpushまで
4. 表示されたURLをDiscord等に通知する（通知の手順は経営管理リポジトリの `$ai-news-discord` スキル）

## 原稿の書き方

1本の記事は「見出し → 3行で言うと → 書き出し → 本文（2〜3節） → どう見るか → メモ → 出典」の順に書く。1号は主記事1本と、短い記事0〜2本。見本は `content/2026-09-30.md` と `content/2026-10-01.md`。

```markdown
---
date: 2026-10-01
scope: Xで話題になった動きを選び、発表元の資料と報道で内容を確かめました
---

号の前書き。2本をつなぐ文脈があるときだけ、1〜3文で書く。

## 何が起きたかと、いちばん大事な数字が分かる見出し

### 3行で言うと

- 見出しに入らなかった、いちばん重要な事実
- 2番目に重要な事実か、判断に必要な条件
- 読者に関係があるか、何をするか（しなくてよいなら、そう書く）

書き出しの段落。場面か、いちばん具体的な事実から始める。上の3行を言い直さない。

### この節の結論を言い切る小見出し

本文。発表元の主張は「〜としています」、確かめた事実は言い切る。

| AI | スコア | 1件の費用 |
| --- | ---: | ---: |
| **A** | **75.2%** | **0.65ドル** |
| B | 71.9% | 1.57ドル |

※表の数字を読むための条件（測った設定、時点、単位）を書く。

### どう見るか

編集部の見方。発表元の利害、この見方が外れる条件、読者が何をするかを、理由を付けて言い切る。

### メモ：使うときの条件

- **使える場所**：本文に書かなかった条件や仕様を書く
- **料金**：100万トークンあたり入力2ドル・出力10ドル

出典：[発表元の発表](https://example.com/announcement)、[第三者の計測](https://example.org/benchmark)
```

### 号の情報（front matter）

- ファイル名は `YYYY-MM-DD.md`（1日1ファイル）。先頭の `---` で囲んだ部分に `date`（必須、ファイル名と同じ日付）と `scope`（話題を確認した範囲。ページ末尾に「この号について：」として表示）を書く。日付がファイル名と違うと生成を中止する
- 公開後に書き直したら `updated: YYYY-MM-DD` を足す。ヘッダーに「○月○日 再編集」と表示される。事実の誤りを直したときは、その記事の末尾に `※` で始まる訂正の注記を書く
- `title` を書くとページタイトルを差し替えられる
- 最初の `## ` より前に段落を書くと、号全体の前書きとして表示される

### 記事の部品

- `## ` で始まる行が1本の記事の見出し。全角スペースで2つの節に分けてもよい。目安は45字前後、上限56字
- `### 3行で言うと`：見出しの直後に青い囲みで表示される要約。箇条書きで3行（1行100字まで）。「だ・である」調
- 要約の直後の段落（要約がなければ見出しの直後の段落）は、書き出しとして少し大きく表示される
- それ以外の `### ` は本文の小見出し。囲みにはならない
- 表は `| 見出し | … |`、`| --- | ---: |`、`| 値 | … |` の形で書く。区切り行の `---:` は右寄せ、`:---:` は中央寄せ。列は4つまで（スマホの幅に収まる数）、1記事に1つまで。数字を含む短いセルは途中で折り返さない
- `※` で始まる段落は注記として小さく表示される。表の直後に条件を書くときと、訂正の注記に使う
- `### どう見るか`：色付きの囲みで表示される意見欄。事実と分けて、編集部の見方を書く
- `### メモ：〜`：記事の末尾に小さな字の囲みで表示される欄。実際に使う人が確かめたい条件・仕様・料金の細目を「`- **項目**：内容`」の箇条書きで書く。囲みは箇条書きで閉じ、続く段落は囲みの外に出る。読了時間には数えない
- `出典：[名前](URL)、[名前](URL)` の行（「出典」「参考」「参照」「一次資料」＋「：」で始まる行）は本文から外れ、記事末尾の出典欄にドメイン付きで表示される
- `> ` で始まる引用は、最終行を `— 発言者` にすると発言の引用として表示される
- 本文中の箇条書き（`- `、入れ子は2スペース下げ）は、列挙が必要なときだけ使う
- 本文中で使えるMarkdownは、リンク `[名前](URL)`・太字 `**語**`・コード `` `語` `` のみ
- 段落の途中で改行しても1つの段落になる。日本語どうしは詰めて結合し、英数字や記号どうしの間には空白を入れる
- 「GPT-6.1」「GLM-5.3」のような名前は、ハイフンの位置で行をまたがないように表示される

### 短い記事（短信）

読者の仕事に関係が薄い話題は、短信にする。見出し・3行・書き出しの1段落・メモ・出典だけで、本文の節と「どう見るか」は書かない。

### 検査（`--check`）

`python3 scripts/build.py --check YYYY-MM-DD` は、その号の構造と、書き方の目安から外れた点を `[注意]` として表示する。目安から外れても生成は止まらない。日付を省くと全号を表示する。生成時（`build.py`）は最新号の `[注意]` だけを表示する。過去の号の `[注意]` は直さない。

| `[注意]` が出る条件 | 目安 |
| ---- | ---- |
| 見出しが長い | 上限56字 |
| 要約がない、3行でない、1行が長い | 3行、1行100字まで |
| 書き出し・出典がない | 必須。出典は本文の事実をたどれるリンク |
| 「どう見るか」がない | 短信以外は必須 |
| 記事が長い | 号でいちばん長い記事（主記事）は2,000字まで、ほかは1,000字まで。字数に表・メモ・出典は含まない |
| 記事が多い | 1号3本まで |
| 表が2つ以上、5列以上 | 1記事に1つ、4列まで |
| メモ欄の行が「**項目**：内容」でない | この形にそろえる |
| 推測で締める文が多い | 「〜そうです」「〜かもしれません」「〜可能性があります」は1記事2回まで |
| 取材の手続きを本文に書いている | 「複数の発信者」「今回読んだ投稿」などは書かない。確認した範囲は `scope` に書く |
| 旧形式が残っている | 小見出しの「（分析）」「ただし」、発言者のない引用（締めの一文）は使わない |

旧形式（見出し → リード → 本文 → 「〜（分析）」 → 「ただし」 → 締めの一文）で書かれた過去の号も、そのまま生成できる。

## 公開設定（初回のみ）

GitHubリポジトリの Settings → Pages で次のとおり設定する。

- Source: Deploy from a branch
- Branch: `main` / `/ (root)`

`.nojekyll` を置いているので、Jekyllの処理は行われずファイルがそのまま配信される。

## デザインを変えるとき

- 見た目は `assets/style.css`、ページ構造は `templates/*.html`、記事内の部品（見出し・要約・表・意見欄・メモ欄・出典欄）は `scripts/build.py` の `render_*` 関数で決まる
- 囲みになる小見出しの語（「3行で」「どう見るか」「メモ」など）は `scripts/build.py` の `*_LABELS`、検査の目安は同じファイルの `TITLE_MAX` などの定数で決まる
- 変更後は `python3 scripts/build.py` を再実行すると、過去の記事もすべて新しいデザインで生成し直される
